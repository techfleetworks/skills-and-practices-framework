# Architecture Decision Records (ADRs)

This folder records the significant architecture decisions behind the framework's data
products (the open-data repository, the query library, and the future hosted service).

An ADR captures **why** a decision was made, the alternatives weighed, and the tradeoffs
accepted, so the reasoning outlives any one conversation. ADRs are numbered, never deleted;
a decision that changes is marked **Superseded** and linked to its replacement.

| ADR | Title | Status |
|---|---|---|
| [ADR-001](ADR-001-static-first-open-data-api.md) | Static-first open-data API | Accepted |
| [ADR-002](ADR-002-library-first-service-later.md) | Library first, hosted service later | Accepted |
| [ADR-003](ADR-003-api-versioning.md) | API and data versioning strategy | Accepted |
| [ADR-004](ADR-004-data-classification.md) | Data classification: public, non-personal | Accepted |

See also the [non-functional requirements](../non-functional-requirements.md) and the
[engineering-standards conformance report](../engineering-standards-conformance.md).
